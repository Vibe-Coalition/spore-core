Welcome to Spore Core

Let's get your agent set up.

Meet Spore Core

An AI agent with a persistent knowledge graph as its identity — not static prompts, not stateless chat. Every conversation adds nodes, edges, and reflections. Over time, it forms a self.

This setup takes a minute. You'll pick a look, create an account, and connect at least one model provider.

Pick a theme

Set the look. You can change this any time in Settings.

Introduce yourself

How should the agent refer to you and be referred to?
The agent will answer to any of these.

Create your account

Secure the instance with a username + password. You'll sign in with this next time.

Choose your providers

Pick which model providers this agent should use. Only providers you enabled in the Plugins step show up here. You'll fill in keys + test them in the next step.

Configure your providers

Fill in API keys, populate model lists, and run the test on each. At least one provider must pass the test before you can finish.

Route model tiers

Pick a provider + model for each tier. Planner is required; others can mirror it.

Vision & audio models (optional)

Specialist tiers for image / video / audio understanding. Skip to use the planner tier for everything.

Pick plugins

Spore Core ships these as optional plugins. Toggle each on or off — recommended ones are preselected. You can change this later in Settings → Plugins.

Voice & web search (optional)

Turn on voice I/O and pick a web search provider. All optional.
Voice providers use the API keys you entered in step 4.
SearXNG is tried first. Brave is used when SearXNG is unset or empty.

What should the agent call you?

A short name or nickname. Defaults to your username.

You're all set 🎉

Your account is ready. Click Continue to start chatting with the agent and exploring the graph.

Browser Automation

Pick the default backend for the browser tool. Setup installs browser-core plus the selected backend; you can enable the other backend later from Settings → Plugins.
You're all set. Click Finish to save and start using your agent.

Spore Code

Spore Code adds CLI session tracking, project context, plan-mode prompt sections, and codebase graph helpers.
If no invite key exists, setup will generate one so Spore Code auth and guest self-registration work immediately. Turn this off if this instance is only for chat/graph use and should not expose coding workflow tools.

Forces an immediate maintainer cycle (bypasses the 15-min interval gate). Triggers gap detection/filling, reflections, stale check, sparse-node connection, dedup, reasoning, and embedding passes.

Context budgets

Override the agent's memory budgets. Leave blank to use the auto-scaled default (which grows with the active model's context window).
When the conversation crosses these limits the agent compacts older turns into a summary. Higher = more memory but more API spend; lower = more aggressive forgetting.
The trigger runs compaction in the background between turns once the on-disk session grows past this size. The tool-result cap is the default truncation; per-tool overrides (e.g. read_file 120k, exec 30k) still apply.

Invite Key

Single host-level secret. Anyone with this key can self-register a webapp account (login screen → Create) and connect via Spore Code. Installing Spore Code during onboarding generates one automatically if none exists. Empty disables both flows. Persists to SPORE_INVITE_KEY in the instance .env.

System Prompt Budgets

Token caps applied when assembling the agent's system prompt. Sections that exceed their cap are silently truncated from the END — leave defaults unless the plan-mode verification logs report missing markers (docker logs ... | grep '[plan-mode]'). Changes apply on the next turn — no restart needed.
Carries project context, sandbox rules, plan-mode block (PHASE 1-5 + QUESTIONS protocol + tooling-question list + RULES). Bump this when you've added prompt content and the agent stops following late-block instructions.
Hard cap on total system prompt size in tokens. The DROP_ORDER list (gaps → anti → selfknowledge → plugin → feed → tooling → runtime → reflections → derived → episodes) trims sections from least-important first when the total exceeds this.
Per-section budgets (advanced — 18 sections)
Override individual sections — leave any field blank to use the default. Unknown keys and non-positive values are silently ignored at boot.

Reset Graph

Destructive. Resets the core memory set: the Default graph and General Knowledge graph are wiped back to seed nodes, and every other graph is removed, including project, channel, user, and custom graphs. Each reset database is backed up before the wipe so the action is recoverable from disk.
Type RESET in the box below to enable the button. Effect is immediate, no restart needed — the app switches back to Default when needed and refreshes the graph list.
